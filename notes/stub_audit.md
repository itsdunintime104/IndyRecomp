# Stub audit: LEGOIndy.exe imports served by stubs

Date: 2026-10-26. Method: static only (capstone over `orig.nosync/LEGOIndy.exe`, byte search for `call rel32`, `jmp rel32` and 4-byte absolute references, Ghidra reference lists from the `indy` project). The game was not run. The boot logs `laneA_boot9.log` and `laneA_boot13.log` were used only to confirm which calls really happen.

## How imports bind

- The import directory has 209 imports. Each one matches an entry in a runtime slice table (`win32_exports_*`, the `K32()` table in `win32_mem.c`, the Bink macro table, and the `d3dx9_35 -> d3dx9_41` alias in `win32_core.c:95-98`). No Indy import falls through to the generated `win32_unsupported.c` stub.
- So the stubs that matter are slice entries whose body is only a stub:
  - the `D3DX_UNREACHED` thunks (`d3dx_misc.c:827-839`),
  - the 17 Bink stubs (`win32_bink.c`),
  - the abort stubs (`win32_mem.c`: `UnhandledExceptionFilter`, `DebugBreak`, `FatalAppExitA`),
  - the unregistered-CLSID path of `CoCreateInstance` (`win32_com.c:91-111`),
  - `GDI32 DeleteObject` (`win32_ui.c:1503-1511`).
- Thunks: the D3DX `jmp [IAT]` thunks are at 0x73FA66-0x73FAAE. IAT slots: D3DXCreateEffect 0x2A17D00, CreateEffectFromFileA 0x2A17D0C, CreateFontA 0x2A17D10, CreateRenderToSurface 0x2A17D24, CreateBuffer 0x2A17D18, CreateEffectCompiler 0x2A17D1C. Bink slots are 0x2A17C4C-0x2A17C8C. CoCreateInstance is at 0x2A17D70.

Not a stub, but it fails on every call: **D3DXCompileShader** (call 0x66BAB9, return 0x66BABE). In boot9 all 44 calls return 0x88760B59 (D3DXERR_INVALIDDATA); in boot13 all 18 do. The vs_3_0 source fails in the vkd3d HLSL front end with `E5003: Statement modifies a const expression`: the shaders assign to globals, which the native d3dx9_35 compiler accepts. Flag 0x200 is D3DXSHADER_AVOID_FLOW_CONTROL, an optimisation hint; it is logged as unsupported (`d3dx_shader.c:1153-1159`). On failure the caller releases the buffers and returns the failure (0x66BAC0-0x66BAEE). I did not trace what the renderer then does with the missing shader: unknown whether it falls back or draws nothing.

## Recommendation, ranked

1. Must fix for normal play: D3DXCompileShader on the game's HLSL. This is not a stub, but no vertex shader compiles at present. Fix it either by accepting writes to non-static globals (treat them as local copies, as the native compiler does) or by giving the shader cache precompiled bytecode.
2. Should build for completeness, not for stability: Bink playback. Today the game skips every movie cleanly. It loses the TT/LucasArts logos, the legal FMV and the demo intro; there is no crash risk, because every caller honours the false return and the per-frame slot cannot run after a failed open.
3. Can stay stubs: D3DXCreateEffect, D3DXCreateEffectFromFileA, D3DXCreateEffectCompiler, D3DXCreateBuffer, D3DXCreateFontA and D3DXCreateRenderToSurface (all in dead functions); BinkOpenDirectSound (never called); the WMI CoCreateInstance (failure gives the correct FALSE); the GameExplorer CoCreateInstance (failure only skips the registration); DeleteObject; the abort stubs (they are reached only after a crash or fatal error).
